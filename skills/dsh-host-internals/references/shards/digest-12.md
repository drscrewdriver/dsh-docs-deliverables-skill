## 0 WHY（一段）

产品代码之外还有一整套"让产品活下来"的工程体系，服务四个场景：每次提交/CI 都要验证（类型/lint/单测/覆盖率/快照/文档保鲜）；docs/ 有严格层级与**字数预算**，目录表**从源码生成**；`.agents/` 存开发 skill 与数千篇决策记录，是 AI 代理的**组织记忆**；可运行样板 = 教程 + keyless 快照测试载体。三条底线：**规则写进文档会漂移，写进脚本才会被执行**；**手写目录必然与源码漂移，生成 + 保鲜才可信**；**示例与测试是一体的**。

## 1 WHAT：职责边界

- **拥有**：`scripts/`（`run-gates.ts` 编排 + `gen-*.ts` 生成 + `verify-*.ts` 保鲜 + `doc-budgets.manifest.json` 预算）、`docs/`（分层 + 生成区 + 双语配对）、`.github/workflows/`（20 条）、`.agents/`（15 skills + Notes 生命周期）、`website/`、`native/system`（唯一参与运行时的工程目录）、`benchmarks/`。
- **不拥有**：任何产品功能（`native/system` 例外，归 digest-05 沙箱叙述）；在线文档托管（CI 部署 `docs-pages.yml`）；本地复演全量（**CI 拥有全量，本地只跑最窄面**）。
- **需求面**：R1 门禁可执行 · R2 文档分层预算（*one home per fact, elsewhere link*）· R3 生成物保鲜 · R4 代理有组织记忆 · R5 样板即测试；N1 最窄检查 · N2 覆盖率门限（`packages/*/*/src` 每文件 100%）· N3 预算 manifest 权威 · N4 双语配对 · N5 keyless 回放。
- **原则**：P1 规则即脚本 · P2 生成即保鲜 · P3 一事实一家 · P4 样板即测试 · P5 代理有记忆。

## 2.2 HOW 骨架

### 门禁：一条命令 = 全部检查，本地只跑最窄面

- `check:all` → `run-gates.ts check-all`（`:82`）；`check:ci:*` 把闸门面细分（静态/lint/覆盖/快照/产物），CI 失败可定位（D1）。
- `doc-sync`（`:193`）聚合文档侧闸门：链接、格式、预算、生成物保鲜、翻译配对、Note 格式收敛到一个入口（P1 物化）。
- 本地纪律（N1）：按改动面选**最窄检查**（`dsh-pre-push-checks` 给选择表），全量交给 CI；N2：`test:coverage`（`:57`）先 `build:native-system`。

### 生成物保鲜：`gen-*.ts` 产、`verify-*.ts` 校

- 物理约定：生成文档自带"禁手改 + 再生成命令"注释（`docs/persistence-catalog.md:1-2` 为范例），生成区用 `<!-- BEGIN GENERATED -->` 包裹（D2）。
- 校验统一 `--check`：`verify-{tool,config,persistence,session-format}-catalog`、`verify-scoped-events`、`verify-module-graph`（行号见表 #1）——**目录过期就是 CI 红**（R3）。
- 0.2.0 生成面显著扩张：除传统 4 张目录表，新增 Cordis API 面 3 张与 client/dependency/doc-graphs 等——**文档↔源码一致性是一个闭环而非几条散线**。

### 文档分层与预算

- 层级分工：`docs/architecture.md`（总览）→ `docs/subsystems/*.md`（**62 篇**，子系统权威）→ cookbook（用法）→ postmortem（事故）；catalog 类多为生成物。
- **一个事实只有一个家**：写在错误层级会被要求改成链接（P3/R2）；预算由 `doc-budgets.manifest.json` 设限，超限/缺文件即拒（`:129`，N3）。
- 双语配对（N4）：`.md` / `.zh.md` + `.i18n.yaml` sidecar 三件套（`native/README.*` 即该形态）。

### 代理组织记忆：skill + Agent Notes

- 15 个 skill 是**可执行的开发纪律**（评审标准、推送前选择、文档与翻译流程、Notes 归档校准、COT 泄漏裁剪）。
- Notes 四态（`:12/:13/:14` + `:38-42`）：`implemented` 以现在时记录已交付现实并随代码同步更新事实；`archived` 冻结、永不作当前权威；`proposed` 不得直接归档；`rejected` 能防错才保留。
- 反中心化（`:19`）：**不建 `INDEX.md`**，检索靠生命周期目录 + 全仓搜索；跨笔记引用用相对链接。规模参照：Notes 1087 → **2444 篇**（R4）。

### 样板与快照：就近示例 + benchmarks

- 旧 R5 意图（示例即测试）保留，载体改变：顶层 `examples/` 已删，CLI 示例落 `apps/cli/config/examples/`，Python 示例落 `python/sdk/examples/minimal.py`（digest-11），性能/回归类另立 `benchmarks/`。
- 快照文化（D4/N5）：`DSH_SNAPSHOT=record/refresh/replay` 三态，`test:snapshot`（`:67`）走 `vitest.snapshot.config.ts`，**无 API key 也能回放真实模型输出**。
